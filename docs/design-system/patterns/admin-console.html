Pattern

Admin console

The admin app: a sidebar, sand pages of panels and tables, every action with a reason and a record in the audit log.

WCAG 2.2 AALight and darkAdmin app

Overview

The admin app (frontend/projects/admin) is a separate application on the same tokens and component stylesheet as the Popkin app, set denser: a sidebar of grouped sections, sand pages of white panels, tables rather than cards. It is for the people who run Popkin, never for members. Every action that changes a person, a Popkin or the platform asks for a reason and lands in the audit log.

When to use what

NeedUse
A list of like recordsData table in a panel, with a toolbar above it
One record's factsKey values
A record's stateStatus pill
Numbers to check firstFigures and tiles, trend chart
Something waiting or doneActivity lists
An action with consequencesA dialog that says what changes and asks why; the outcome is a toast

Structure

Every signed-in page is the admin shell, a page header, then panels in a grid. Signed out, the admin sign-in card.

States

  • Loading: skeletons in each panel in the panel's shape; the header and shell are there at once.
  • Error: the panel says it couldn't load, nothing changed, Try again and Open Health.
  • Empty: says why it is empty in a good way (No reports waiting).
  • No results: the filters stay, with a way to clear them.
  • Viewer: a notice under the bar; every action disabled with the reason as its tooltip.
  • Done: a toast says what happened and that it is in the audit log.

Responsive behaviour

  • Under 1024 px the sidebar becomes a drawer behind a top bar; the environment stays on screen.
  • Under 768 px tables stack into records.
  • Panel grids are one column under 1024 px.
  • Dialogs are bottom sheets under 640 px.

Accessibility

  • One <h1> per page, panels titled with <h2>; landmarks: the Admin nav, main.
  • Tables are real tables with column headers.
  • States are said in words (status pills, hidden "(urgent)", Allowed), never colour alone.
  • A disabled action keeps its name and gives its reason as a tooltip.
  • Dialogs trap focus and return it to the button that opened them.

Content

  • Plain and exact: say what happened, where and since when (Reconnects up 4× on eu-west-2 since 10:10).
  • Name the admin who did a thing.
  • Use Popkin's words: Popkin, Host, members, wrap up, invite code. Never "trip".
  • Never show a secret, a code a person is signing in with, or more of a person than the task needs.

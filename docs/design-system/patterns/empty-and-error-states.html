Pattern

Empty and error states

An empty place says what it is for and offers the first step. A failure keeps the chrome, says nothing was lost and offers Try again.

Overview

Every list has a first-use empty state and, where it filters, a no-results state. Every screen that loads data has an error state. Whole-app failures are pages: not found, something went wrong (with a reference code), offline.

When to use what

KindSaysOffers
First useWhat this is forThe first action
FilteredNothing matches this filterThe action, and Show all
ErrorWhat happened; nothing was lostTry again, and a way back
Not foundThe link is broken or movedMy Popkins, the home page
Server errorIt is on our sideTry again; reference code
OfflineThis needs a connectionTry again; saved Popkins

States

  • First use, filtered, error, not found, server error, offline.

Responsive behaviour

  • Centred in the content area; the chrome stays.

Accessibility

  • A heading for the state; error versions in role="alert".
  • The first action receives focus when the state replaces content the person was using.

Content

  • Warm and specific: "No photos yet" not "No data".
  • Never blame: "We couldn’t…".

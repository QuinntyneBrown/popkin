Pattern

Forms

Popkin asks for very little: a name, a way to reach you, a code. Each step is one screen with one question and one action at the thumb.

Overview

Forms are step screens (sign up, name your Popkin, how long) or dialogs (edit, share an experience, comment). Pages never hold inline editing forms; a button opens a dialog or a step.

When to use what

NeedUse
One or two answers that start somethingA step screen with step dots
Changing something that existsA dialog from the screen
A choice between a few options with consequencesChoice cards
A binary settingA switch with a written consequence

States

  • Ready: the action is enabled when the form can be sent; disabled only when the reason is obvious (no name yet).
  • Invalid: inline error under each field, a summary at the top, focus on the summary.
  • Submitting: the button is busy with a present-tense label; fields are read-only.
  • Failed: an alert above the fields says nothing was lost; the button is enabled again.
  • Done: the next step opens; changes in a dialog close it and confirm with a toast.

Responsive behaviour

  • One column at every width.
  • The action sits in the sticky footer; the keyboard pushes it up, never covers it.

Accessibility

  • Visible labels; autocomplete and inputmode on every field.
  • Validate on submit, then re-check a field as it changes.
  • The six-digit code accepts paste and one-time-code autofill.

Content

  • One question per screen, as a sentence: "First, what should we call you?"
  • Help is reassurance: "That’s all we need. No passwords."

Theming

Two themes, light and dark, plus the Popkin colour: each Popkin picks one of seven colours and its screens take it on.

Overview

Light is :root. Dark applies with [data-theme="dark"], or automatically when the device prefers dark and the page has not chosen light. Each theme sets color-scheme so native controls follow. A person can choose Match my device, Light or Dark in their account.

Token tiers

  • Primitives: --palette-*, never used by components.
  • Roles: --color-*, --text-*, --space-* and the rest; themes override these only.
  • Popkin colour: --accent and what derives from it.
  • Component: a component may alias roles under its own name when it needs re-skinning.

Popkin colour

Set data-accent="teal" (or coral, sky, berry, leaf, plum, amber) on a screen, card or avatar. Everything under it reads --accent and the values mixed from it: --accent-tint (cards, frames), --accent-wash (whole screens), --accent-edge (tile edge), --accent-text (the colour as text, darkened in light and lightened in dark) and --accent-line (edges, rings and dots, lightened in dark). The strengths are theme tokens, so dark tints are stronger and text mixes toward white.

Adding a theme

Add a [data-theme="name"] block that overrides role tokens only, add it to the prefers-color-scheme rule if it is automatic, extend contrast-pairs.json and run the contrast check. To add a Popkin colour, add --palette-accent-name, a [data-accent="name"] rule, and check white on it (4.5:1) and the mixed pairs.

tokens.json

tokens/tokens.json is the DTCG export of tokens.css ($type, $value, aliases as {group.token}, dark values under $extensions). Regenerate it with the skill's tokens_to_json.py whenever tokens.css changes. The Angular app copies tokens.css into the components library.

Do and don't

  • Do set data-accent once on the screen and let components inherit it.
  • Don't write a Popkin colour as a hex value in a component.
  • Don't invert light values to make dark; dark is built from its own roles.

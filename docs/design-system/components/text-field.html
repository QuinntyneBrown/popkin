Component · Inputs

Text field

A label, a 56px field with a 2px edge, and a line of help or error under it. Popkin asks for very little, so each field is large and calm.

WCAG 2.2 AAStatus: stableNative <input>

Overview

Use a text field for one line: a name, a phone number, an invite code. Use a textarea for comments. Every field has a visible label; the placeholder is only an example.

Anatomy

  1. LabelNunito 800, 15px, above the field.
  2. Field56px, 16px radius, 2px --color-border-strong edge, white.
  3. Help or errorInter 14px under the field; an error replaces the help and adds an icon.

Responsive behaviour

  • Fields fill the column at every width; the column is at most 28rem.
  • Inputs use inputmode and autocomplete so phones show the right keyboard.

Theming

Reads --color-bg-surface, --color-border-strong, --color-border-focus (deep coral, 3:1) for the focused edge and --shadow-focus for the halo. In dark the field is the raised night card.

Accessibility

Role and pattern

Native <input> with <label for>.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
TypingEdits; Enter submits the form.

Focus

The edge turns coral and a 4px coral halo appears; the halo does not move layout.

Labelling

Visible label always; help and error joined with aria-describedby; aria-invalid="true" on error. Errors say how to fix it. The 6-digit code field uses autocomplete="one-time-code".

Content

  • Labels are nouns: "Your name", "Phone number", "Invite code or link".
  • Help is one friendly line: "First name is plenty."
  • Errors name the problem and the fix: "That number looks a digit short."
  • Mark optional fields "(optional)"; never mark required ones with an asterisk.

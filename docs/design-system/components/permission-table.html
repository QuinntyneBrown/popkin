Permission table and role select

What each role may do, as a table of permissions by role with a tick or a dash and the word for each, and the select that sets an admin's role.

Overview

Use on Admins & roles: the table explains the roles; the select changes one admin's role, which asks for a reason.

Anatomy

  1. Role columnperm-table__role: the role and how many admins have it.
  2. Permission rowGrouped by area: People, Popkins, Operations, Platform, Access.
  3. CellA tick or a dash, with visually hidden Allowed or Not allowed.

Sizes

One size.

States

The select follows the field's states; on your own row it is disabled with the reason.

Responsive behaviour

  • The table scrolls sideways inside its panel under 768 px, keeping the permission column readable.

Theming

Ticks read --color-success-fg, dashes --color-fg-subtle.

Accessibility

Role and pattern

A native table with row and column headers; a native <select>.

Keyboard

KeyAction
Tab / Shift+TabMoves focus through the links and buttons in DOM order.
↑ ↓Choose a role in the select.

Focus

The shared ring: --focus-ring-width of --color-focus-ring at --focus-ring-offset, on :focus-visible only.

Labelling

Each cell says Allowed or Not allowed in hidden text, so the tick is not the only sign; the select is labelled "Role for Aiko Tanaka".

Contrast

Tick
Dash

Motion

None.

Touch

The select is 40px tall.

Content

  • Permissions are verbs: Suspend and restore, End live calls.

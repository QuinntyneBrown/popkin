Screen and layout

A screen fills the width it is given: a top bar, a body with 24px sides, and a sticky footer for the main action. Modifiers say how it uses a wider screen. Stack and cluster space everything inside it.

Overview

Every app screen is a .screen, full width at every size. .screen--app puts it in the Popkin's shell, .screen--split gives it a picture half from 768px, .screen--page and .screen--column hold a top-level page and a single centred column. The landing page uses the 72rem container instead.

Anatomy

  1. Top barBack and title.
  2. Body16px top, 24px sides.
  3. FooterSticky, fades the content behind it, holds the main action.

Responsive behaviour

  • Below 768px: one column; inside a Popkin the tabs sit along the bottom.
  • From 768px: .screen--app makes room for the side rail (a sidebar from 1024px); .screen--split gives the left 44% to its .split-aside (50% from 1024px, 55% from 1280px) and centres the form in the rest.
  • From 1024px: .screen--list and .screen--thread put the thread list and a thread side by side; from 1280px a thread adds its .detail-pane.
  • Forms never grow wider than 28rem, 32rem from 640px and 36rem from 1024px.

Theming

--color-bg-canvas; washed screens --accent-wash; the stage --color-bg-stage.
